# 三节点联盟链支付实验

这是用于架构师考试知识点学习的最小实现，不是生产级区块链。

## 四类区块链特点

| 特点 | 本项目的实现 | 运行时能观察到什么 |
|---|---|---|
| 密码学 | Ed25519交易签名、SHA-256区块哈希链 | 修改交易金额后旧签名失效；每个区块引用前一区块哈希 |
| 智能合约 | `PaymentContract`确定性校验规则 | 签名正确但金额为负数的交易仍被合约拒绝 |
| 共识机制 | 三节点教学用多数表决 | node1、node2赞成，模拟拜占庭节点node3反对，2/3仍能提交 |
| 分布式存储 | 三个Docker volume各保存一份SQLite账本 | 三个节点的区块内容、链顶哈希和账户状态最终一致 |

> 这是为了理解原理而实现的最小联盟链，不是完整的PBFT、Raft、PoW或生产智能合约平台。

## 系统结构

```text
                 提交带Ed25519签名的交易
Alice客户端 ─────────────────────────────> node1（提议节点）
                                               │
                         ┌─────────────────────┴─────────────────────┐
                         │                 多数投票                   │
                         ↓                                            ↓
                    node2：赞成                                  node3：故意反对
                         │                                            │
                         └──────────────── 2/3通过 ───────────────────┘
                                               │
                                   生成SHA-256链接的新区块
                         ┌─────────────────────┼─────────────────────┐
                         ↓                     ↓                     ↓
                 node1-data/ledger.db  node2-data/ledger.db  node3-data/ledger.db
```

每个节点都会独立执行同一个`PaymentContract`。节点不会直接信任客户端给出的余额，而是根据本地区块账本重新计算状态。

## 运行

每次从全新的创世区块开始：

```bash
docker compose down -v
docker compose up -d --build
python3 -m pip install -r requirements.txt
python3 demo.py
```

`demo.py`会按顺序运行四个实验：

```text
1. 密码学：正常验签，并演示篡改金额导致验签失败
2. 智能合约：提交负数金额，观察合约拒绝原因
3. 共识机制：显示三个节点的逐票结果和2/3法定票数
4. 分布式存储：比较三个SQLite副本、完整哈希链和链顶哈希
```

查看各节点状态：

```bash
curl http://127.0.0.1:8001/state
curl http://127.0.0.1:8002/state
curl http://127.0.0.1:8003/state
```

查看节点展示的四类机制：

```bash
curl http://127.0.0.1:8001/features
```

查看完整区块链：

```bash
curl http://127.0.0.1:8001/chain
```

查看日志和停止环境：

```bash
docker compose logs -f
docker compose down
```

删除容器和三个节点的账本数据，重新从创世区块实验：

```bash
docker compose down -v
```

## 代码对应关系

| 文件 | 作用 |
|---|---|
| `src/crypto_utils.py` | Ed25519密钥、签名、验签和SHA-256 |
| `src/contract.py` | 支付智能合约的确定性验证规则 |
| `src/ledger.py` | SQLite区块存储、状态计算、哈希链完整性检查 |
| `src/node.py` | 节点HTTP接口、多数投票、区块复制 |
| `demo.py` | 串联四个可观察实验 |

## 软考概念与本例的边界

- **密码学**保证身份、完整性和防篡改，但不等于数据保密。本例签名交易，没有加密交易内容。
- **智能合约**是各节点确定性执行的业务规则，不等于传统纸质合同，也不代表规则天然正确。
- **共识机制**解决多个节点对账本结果达成一致的问题。本例只是多数表决，不能替代正式BFT协议。
- **分布式存储**表示多个节点各自持有账本副本，不等于普通数据库简单地复制一张表。
